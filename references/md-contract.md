# MD 输入契约（转 EPUB 前必须满足）

md2epub 只对满足本契约的 Markdown 负责。生产端（OCR 整理、Word/PDF 转换、人工写作）应按此产出；不满足时先跑 `md2epub.py lint` 看具体问题。

## 1. 标题

| 层级 | 用途 | 例 |
|---|---|---|
| `#` | 书名（全文仅一个，可省略——省略时用配置里的 title） | `# 最高人民法院民事诉讼证据规则` |
| `##` | 部分／卷 | `## 第一部分 2020年《证据规定》条文` |
| `###` | 篇／条（分章单位） | `### （修改）第一条【起诉证据】` |
| `####` | 节 | `#### 法条渊源` |
| `#####` | 子节 | `##### 一、共同诉讼概述` |

硬要求：
- 层级连续，不跳级（`##` 之后不能直接 `#####`）。
- 不把列表项、案号、页码误标成标题。
- 标题行不换行、不加粗、不带句末标点。

## 2. 段落

- **一行一段**，段内不硬换行（PDF 复制出来的 40 字一换行必须合并）。
- 段落之间用空行分隔。
- 段落缩进由 CSS 负责，md 里不要写空格或全角空格缩进。
- 单段建议 < 1500 字；2000 字以上会告警（多半是几段被合并）。

## 3. 表格

- 标准管道表，第一行是表头，第二行是 `|---|`。
- 每行列数与表头一致；缺失的单元格留空，不要省略竖线。
- 不用合并单元格；跨行跨列在 md 里展开成普通列。
- 不残留 `<fcel> <ecel> <lcel> <ucel> <nl>` 等 OCR 结构标记。
- 超长表（>30 行）可以整表保留，`build` 会自动分段并重复表头。

## 4. 脚注

- 正文角标用 ①②③…⑳，紧跟被注释内容之后。
- 注释行写成引用块，放在**同一章节内**的任意位置（通常紧跟所在段落后）：

```
……这是一段正文。①

> ① 胡亚球：《论民事起诉证据》，载《法学》1998 年第 11 期。
```

- 原书按页编号的 ①，同一章里会重复；`build` 会按章重排编号并合并完全相同的注释。
- 普通引用（非脚注）也用 `>`，但开头不是圈号，会按引用块渲染。

## 5. 图片

- 语法：`![图 1 股权结构示意](images/fig1.png)`，alt 必填（同时用作图注）。
- 路径相对 md 所在目录，**只含 ASCII 小写字母、数字、`-`、`_`**；大小写必须与磁盘一致。
- 只用 PNG / JPEG / GIF / SVG；不要 TIFF、BMP、HEIC、WebP。
- 单张长边建议 ≤ 1600 px、≤ 1.5 MB；`build` 会原样打包，不做有损压缩。
- 远程图片（`http://`）不支持自动下载，需先落盘。

## 6. 不要出现

- 页眉、页脚、页码、"续表"标题、扫描水印。
- md 自带目录（`## 目录` 及条目）；`build` 会剥离，但最好在 md 侧就不生成。
- HTML 注释、`<!-- page 12 -->` 之类标记。
- OCR 残留：`<fcel>`、`□□`、孤立数字行、重复字符（"潭潭州"）。
- 中英混排里多余的空格（"第 一 条"）。

## 7. 编码与标点

- UTF-8 无 BOM。
- 中文标点统一全角（，。；：？！“”‘’（）《》），半角括号只保留在法条编号、年份等必要处。
- 省略号统一 `……`，破折号统一 `——`。

## 8. 自检

```bash
python3 ~/.agents/skills/md2epub/scripts/md2epub.py lint book.md
```

- 退出码 0：可转。
- 退出码 1：有阻断项（缺图、表格标记残留、无标题、编码错误），必须先修。
- 提醒项不阻断，但会影响成品观感，建议一并处理。
